AUD-20261127-QUALITY-001fixedmediumquality-maintainabilitydrive/browse.rs snippet() allocates two full Vec<char> copies of extracted PDF text per search result
`snippet(text: &str, term: &str)` in `crates/server/src/drive/browse.rs:119-142` collects the entire extracted text of each matching Drive document into `chars: Vec<char>` and a second `lowered: Vec<char>` (8 bytes per character), then runs an O(N*M) `windows(needle.len()).position(...)` scan. `search()` (`crates/server/src/drive/browse.rs:175-191`) fetches full `df.text` (up to `CAP = 200_000` characters per file in `jobs/drive_text.rs:16`) for up to 60 matching files per request, causing up to ~96 MB of transient heap allocations and quadratic worst-case CPU work per search query.		7fa950en/a (fixed on main in v0.6.0)confirmedconfirmedno
AUD-20261127-OPS-001fixedlowoperationsSwift API.swift force-unwraps URLComponents and Session.normalize does not restrict schemes to http/https
In `app/Atlas/Core/Session.swift:111-119`, `Session.normalize(_ address: String)` prepends `http://` only when `!text.contains("://")`, and does not verify that `components.scheme` is `"http"` or `"https"`. Any scheme containing `://` with a non-empty host (for example `ftp://...` or `file://host/...`) passes `normalize()` and `Session.connectLink(_:)`. Separately, `app/Atlas/Core/API.swift:55-66` force-unwraps `URLComponents(url: ..., resolvingAgainstBaseURL: false)!` and `components.url!`.		410e5den/a (fixed on main in v0.6.0)confirmedconfirmedno

AUD-20261127-QUALITY-003fixedlowquality-maintainabilityUnchecked Mutex and RwLock unwrap() calls in server request and worker paths
Multiple request handlers and background loops in `crates/server/src/` call `.lock().unwrap()` or `.read().unwrap()`/`.write().unwrap()` on `std::sync::Mutex` / `std::sync::RwLock`.
