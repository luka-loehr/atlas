## Summary

`GET /v1/drive/files/{id}/thumb` (`crates/server/src/drive/blobs.rs:106-167`) invokes `pdftoppm` inside `tokio::task::spawn_blocking` with a 60-second timeout whenever a PDF thumbnail is not yet cached on disk, with no concurrency limit or per-hash deduplication. In addition, `atlas_core::process::output()` (`crates/core/src/process.rs:19-39`) drains both `stdout` and `stderr` with unbounded `pipe.read_to_end(&mut bytes)` in background threads, so a malformed PDF or media file that produces large output can exhaust server memory before the deadline expires.

## Evidence

- `crates/server/src/drive/blobs.rs:122-142`: checks `try_exists(&dest)` and immediately calls `spawn_blocking` -> `first_pdf_page(&source)` with no semaphore or in-flight map.
- `crates/server/src/drive/blobs.rs:146-161`: calls `atlas_core::process::output(Command::new("pdftoppm").args([...]).arg(pdf), Duration::from_secs(60))` without `--` argument separation and with no output byte cap.
- `crates/core/src/process.rs:19-27`: `pipe.read_to_end(&mut bytes)` buffers the entire stdout and stderr streams in memory without a maximum byte limit.

## Risk

Multiple concurrent requests for uncached PDFs (or repeated requests for the same uncached PDF before the first render finishes) spawn parallel `pdftoppm` processes and exhaust CPU, RAM, or Tokio blocking threads. A crafted PDF or media file causing noisy stdout/stderr in `pdftoppm`, `pdftotext`, or `ffmpeg` can trigger OOM before the subprocess timeout fires.

## Fix and current state

Open. Gate on-demand `drive/blobs.rs` thumbnail generation behind a bounded `tokio::sync::Semaphore` (e.g. 2-4 permits) and per-hash singleflight deduplication, pass `"--"` before the file path where supported, and add a configurable maximum byte cap (e.g. `.take(max_bytes)`) in `atlas_core::process::output` (or a bounded variant) so subprocess stdout/stderr cannot grow without bound.

## How to verify

- Add a unit test in `crates/core/src/process.rs` confirming that a subprocess emitting output above the cap is terminated or truncated cleanly without unbounded allocation.
- Verify `drive/blobs.rs` enforces a bounded concurrency semaphore on thumbnail rendering.
