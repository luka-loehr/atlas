## Summary

Both WebSocket endpoints — `GET /v1/system/terminal` (`crates/server/src/system/terminal.rs:17-23`) and `GET /v1/system/live` (`crates/server/src/system/metrics/mod.rs:229-231`) — accept `WebSocketUpgrade` without inspecting the HTTP `Origin` header. In addition, `/v1/system/terminal` spawns `bash -l` via `portable_pty::CommandBuilder::new("bash")` without scrubbing sensitive server environment variables (`ATLAS_TOKEN`, `ATLAS_SHARE_TOKEN`, `DATABASE_URL`) and without bounding concurrent PTY sessions or idle session lifetime.

## Evidence

- `crates/server/src/system/terminal.rs:17-23`: `pub async fn terminal(ws: WebSocketUpgrade) -> Response` accepts no `HeaderMap` and performs no `Origin` check before calling `ws.on_upgrade(...)`.
- `crates/server/src/system/metrics/mod.rs:229-231`: `pub async fn live(State(app): State<AppState>, ws: WebSocketUpgrade) -> Response` performs no `Origin` check before upgrading.
- `crates/server/src/system/terminal.rs:43-47`: `CommandBuilder::new("bash")` inherits the parent `atlas-server` process environment (populated from `/etc/atlas/atlas.env` by systemd) without removing `ATLAS_TOKEN`, `ATLAS_SHARE_TOKEN`, or `DATABASE_URL`, and `terminal()` imposes no semaphore cap on concurrent PTY sessions.

## Risk

Without `Origin` validation, any browser-based client or future cookie/proxy-authenticated setup is exposed to Cross-Site WebSocket Hijacking (CSWSH) against a route that directly spawns an interactive shell. Furthermore, inheriting `/etc/atlas/atlas.env` variables into the PTY shell exposes `DATABASE_URL` and `ATLAS_SHARE_TOKEN` to any command or child process run inside the terminal, and unbounded PTY spawning allows file-descriptor and process exhaustion.

## Fix and current state

Fixed in `7fa950e`. Added `iam::verify_ws_origin` enforcing same-host `Origin` on WebSocket upgrades (`require_v1_auth` and `/v1/system/terminal`), scrubbed `ATLAS_TOKEN`/`ATLAS_DATABASE_URL`/`ATLAS_SHARE_TOKEN` via `env_clear()` whitelist in PTY spawn, and bounded concurrent PTY sessions to `MAX_TERMINALS = 4`.

## How to verify

- Unit/handler test sending `Origin: https://untrusted.example.com` to `/v1/system/terminal` and `/v1/system/live` receives `403 Forbidden` before upgrade.
- Verify `terminal.rs` removes `ATLAS_TOKEN`, `ATLAS_SHARE_TOKEN`, and `DATABASE_URL` from `CommandBuilder` and rejects sessions above the configured concurrency cap with `429 Too Many Requests`.
