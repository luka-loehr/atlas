## Summary

The global `/v1` authentication middleware (`crates/server/src/auth.rs:13-35`) accepts the master bearer token in the `?token=` query parameter for every route under `/v1`, not only read-only media playback routes. This includes high-privilege endpoints such as `GET /v1/system/terminal`, `GET /v1/system/live`, `POST /v1/system/power/{action}`, and all Photos, Drive, and Share mutation endpoints. Query-string credentials routinely leak into reverse-proxy access logs, browser history, `Referer` headers, and crash/diagnostic traces.

## Evidence

- `crates/server/src/main.rs:210-221`: `auth::require_token` is applied as a single `.layer(...)` over all merged `/v1` routers (`photos`, `drive`, `system`, `share`).
- `crates/server/src/auth.rs:21-35`: `presents_token()` falls back unconditionally to `req.uri().query()` matching `token=` with `ct_eq`, regardless of HTTP method or route path.
- `crates/server/src/auth.rs:57-66`: unit test `accepts_the_token_in_header_or_query` confirms `?token=` is accepted on arbitrary `/v1` paths.

## Risk

Any client or reverse proxy that logs URLs with query strings records the master `ATLAS_TOKEN` in plaintext. Combined with the single-token architecture where `ATLAS_TOKEN` grants interactive PTY shell access (`/v1/system/terminal`) and host power control, query-string exposure widens credential leakage blast radius.

## Fix and current state

Open. Restrict `?token=` acceptance in `auth.rs` strictly to GET/HEAD requests on read-only media endpoints (such as `/v1/assets/{id}/video`, `/v1/assets/{id}/original`, `/v1/assets/{id}/thumb/{size}`, `/v1/drive/blobs/{hash}/{name}`), or issue short-lived, media-scoped signed tokens for players that cannot send `Authorization` headers. Reject query tokens on all `POST`/`PUT`/`PATCH`/`DELETE` routes and on `/v1/system/*`.

## How to verify

- Add unit tests in `crates/server/src/auth.rs` verifying that `POST /v1/system/power/restart?token=...`, `GET /v1/system/terminal?token=...`, and `POST /v1/assets/delete?token=...` return `401 Unauthorized`, while `Authorization: Bearer ...` continues to succeed.
