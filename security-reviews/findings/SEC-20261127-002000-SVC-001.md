## Summary

Multiple batch JSON endpoints accept unbounded `Vec` arrays and pass them directly to PostgreSQL `ANY($1)` clauses or recursive CTEs without checking array length:
- `POST /v1/assets/exists` (`crates/server/src/photos/assets/upload.rs:17-32`: `hashes: Vec<String>`)
- `POST /v1/assets/{favorite,archive,lock,trash,restore,delete}` (`crates/server/src/photos/assets/state.rs:11-82`: `ids: Vec<String>`)
- `POST /v1/drive/move` (`crates/server/src/drive/organize.rs:139-193`: `files: Vec<i64>`, `folders: Vec<i64>`, passed into `WITH RECURSIVE below`)
- `POST /v1/drive/trash`, `/v1/drive/trash/restore`, `/v1/drive/trash/delete` (`crates/server/src/drive/trash.rs:16-67`: `ids: Vec<i64>`)

## Evidence

- `crates/server/src/photos/assets/upload.rs:23-27`: executes `SELECT id FROM assets WHERE id = ANY($1)` with `&b.hashes` directly, with no length bound.
- `crates/server/src/photos/assets/state.rs:56-66`: executes `UPDATE assets SET trashed_at = now() WHERE id = ANY($1)` and `share::assets_hidden(app, &b.ids)` with unbounded `b.ids`.
- `crates/server/src/drive/organize.rs:158-173`: passes unbounded `b.folders` into a recursive CTE `WITH RECURSIVE below AS (SELECT id FROM drive_folders WHERE id = ANY($1) UNION ALL ...)`.
- `crates/server/src/drive/trash.rs:34-67`: passes unbounded `b.ids` directly to `UPDATE`/`DELETE ... WHERE id = ANY($1)`.

## Risk

While Axum's default 2 MiB JSON extractor limit bounds raw HTTP body size, a 2 MiB JSON array of integer IDs still encodes hundreds of thousands of IDs in a single request, causing long-running PostgreSQL array scans, lock contention, recursive CTE amplification in `drive/move`, and high server memory churn.

## Fix and current state

Open. Enforce explicit per-request batch caps (for example `MAX_BATCH_IDS = 5_000` for `/v1/assets/exists` and `1_000` for mutation endpoints `/v1/assets/*`, `/v1/drive/move`, `/v1/drive/trash/*`), returning `400 Bad Request` when exceeded.

## How to verify

- Add unit/handler tests verifying that payloads exceeding the batch limit on `/v1/assets/exists`, `/v1/assets/trash`, `/v1/drive/move`, and `/v1/drive/trash` return `400 Bad Request`.
